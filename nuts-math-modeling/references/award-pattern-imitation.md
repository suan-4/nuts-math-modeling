# Award-Pattern Structural Imitation

Use award papers to learn reasoning architecture, evidence placement, and sentence-function order. This is structural imitation, not textual copying.

## What to imitate

- question decomposition and dependency contracts;
- model-choice reasoning from problem properties;
- derivation order and intermediate-result placement;
- formula-diagram-table-text coordination;
- validation matched to the exact claim;
- transitions that carry an output into the next operation.

Do not copy award-paper sentences, figures, tables, source code, problem-specific derivations, data, or conclusions. Cite borrowed nonstandard methods or relations where required.

## Pattern extraction record

For every reusable pattern record:

| Field | Content |
|---|---|
| Source | Paper identifier and source page |
| Local goal | What the original passage had to establish |
| Preconditions | Problem/data properties that made the pattern valid |
| Reasoning sequence | Need, input, operation, output, interpretation, next decision |
| Evidence form | Formula, diagram, figure, table, test, or comparison |
| Sentence-function sequence | Define, justify, derive, report, interpret, decide, validate |
| Transfer rule | Other tasks where the same logic applies |
| Non-transferable residue | Original object, names, values, notation, and special assumptions |
| Weakness | What should not be copied despite award status |

## Transfer workflow

1. Diagnose the current manuscript's missing reasoning link.
2. Retrieve a pattern by subproblem property and evidence need, not by A/B/C label.
3. Verify that the pattern preconditions hold in the current problem.
4. Map every pattern role to current formulas, code, data, and outputs.
5. Draft from the current evidence using the sentence-function sequence.
6. Remove all problem-specific residue from the source case.
7. Check mathematical validity, originality, and paper-wide consistency.

If a slot has no current evidence, list it as an evidence gap. Do not fill it with an award-paper value or generic claim.

## High-value pattern library

### Mechanism to computable recurrence

`define state/coordinates -> expose local geometry -> labeled diagram -> derive invariant/constraint -> obtain recurrence -> transform to computable coordinates`

### Complex optimization decomposition

`show decision dependency -> prove simplifying condition -> explain full-space difficulty -> split layers -> define layer contract -> solve -> recompute feasibility`

### Statistical condition to model choice

`identify analysis unit/dependence -> exploratory evidence -> select model family -> fit/compare -> diagnose assumptions -> interpret -> pass estimates to decision model`

### Correction model

`derive base model -> verify independently -> derive applicability criterion for omitted mechanism -> evaluate criterion -> correct only affected cases -> compare conclusions`

### Figure/table as a decision bridge

`state claim -> show pattern in figure -> report selected exact values in table -> interpret -> use value/threshold in next formula or policy`

## Originality audit

Before delivery:

- search for source-specific nouns, object names, symbols, values, and sentence fragments;
- check whether paragraph order follows current reasoning rather than mechanically shadowing one source;
- ensure every figure and table is regenerated from current data/code;
- distinguish standard mathematical formulas from source-specific derivations;
- cite nonstandard borrowed methods and never disguise quotation as paraphrase.

Evaluate the Skill on held-out problems and source pages. Success means the reasoning pattern transfers while source language and problem-specific residue do not.
